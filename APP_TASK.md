## Behavior and UI

- No whitelist/registration. The action resolves the actual foreground window at hotkey receipt. Default bindings: Delete mute toggle; PageUp +5 percentage points; PageDown -5. Volume clamped 0..100, per-session relative changes; volume keys preserve the current mute state. Toggle semantics for multiple sessions: if all muted, unmute all, otherwise mute all.
- Global RegisterHotKey with stable IDs; MOD_NOREPEAT for mute, optional native repeat for volume. No low-level keyboard hook/injection/driver. Target remains direct foreground PID or verified descendants running the SAME absolute executable path (existing Targeting). Exclude system sounds, cross-process and expired sessions. Enumerate fresh across all active render endpoints for each action; no endpoint/master volume fallback.
- Resolve process identity and selected sessions; refresh/validate original values before mutation using existing Eligibility/TryRefreshOriginals. Recheck actual foreground PID immediately before writing. If no matching session, or values cannot be read, show honest status without altering anything. If a partial write fails, attempt to restore changed sessions' original values and report failure; never silently claim success. Ensure errors per COM call cannot crash the message loop.
- Use the same audio action method for UI/WM_HOTKEY and testable logic; don't fork separate simulation behavior.
- Compact Korean settings window, roughly 680x500 logical pixels, resize/DPI-safe layout (TableLayoutPanel/FlowLayoutPanel/Dock), readable Segoe UI/Malgun Gothic. Three labeled shortcut rows, each key selector (human-readable Delete, Page Up, Page Down, F1-F11, letters, digits and common navigation keys) plus Ctrl/Alt/Shift checkboxes. No Windows modifier. A single Save/Apply button, optional defaults button, volume step NumericUpDown 1..20 default 5, and a clear enabled/pause control. Key selection must be fully keyboard accessible. No custom-drawn complex widgets.
- Show a short visible notice: while enabled these hotkeys replace the keys' ordinary functions in other apps; pause or choose modifiers to restore ordinary Delete/PageUp/PageDown behavior. Suspended automatically while this app's own settings window/dialog is foreground so settings remain editable. Do not ignore own-process focus events. Track foreground via SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT), keep delegate alive, unhook on exit. Avoid high-frequency polling.
- Show current enabled/paused/settings-suspended/conflict state and last action target/result, or no-audio/access failure. Never steal focus or display popups over another application. Tray tooltip can be short; full message in settings window.
- Tray icon with Show Settings, Pause/Resume, Exit. Minimize/close hides to tray; include clear text explaining close-to-tray. Explicit Exit removes tray icon, unregisters hotkeys/unhooks event and exits process. Prevent duplicate instances (user-session mutex); on second launch show existing settings or a clear existing-instance message without adding another hotkey listener.
- Defaults enabled, but first launch shows settings and suppresses hotkeys while settings has focus. On returning to another app, activate configured shortcuts. In paused mode no keys are registered. While running and enabled, keys are reserved even if foreground app has no audio (be clear about this in UI/README).

## Settings and hotkey validation

- Persist only three binding values/modifiers, step and enabled state in %LOCALAPPDATA%\GameAudioKeys\settings.json. Validate enum/key range/modifier mask, step bounds, duplicate combinations, bare modifiers, F12 and unsupported/reserved combos (especially Ctrl+Alt+Delete, Alt+Tab, Ctrl+Escape and Windows combos). No hidden broad key swallowing. Support user's requested bare Delete and PageUp/PageDown.
- Save atomically (temporary sibling file + replace/move). On corrupt/invalid config preserve original and show readable status; use defaults in memory, don't silently destroy corrupt contents. Keep testing config in temporary paths. No secret data in config.
- Registration failures need actionable Korean error and rollback: if a set partially registers, unregister partial IDs. If applying new settings fails, preserve/restore old working settings and bindings. Validate proposed registrations while saving even though settings window is currently suppressing them; release temporary registrations afterward. Don't silently save a permanently conflicting shortcut as success. No administrator privilege request by default.
- UI changes, tray pause, focus changes and startup must use one consistent registration lifecycle, with cleanup during app exit/handle changes.
