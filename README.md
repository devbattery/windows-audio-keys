# Windows Audio Keys

현재 활성(포그라운드) 애플리케이션의 오디오만 빠르게 음소거하거나 볼륨을 조절하는
Windows 11 트레이 유틸리티입니다. 프로그램을 미리 등록할 필요 없이,
단축키를 누르는 순간 실제 포그라운드 창의 PID를
확인하고, 그 프로세스(또는 같은 실행 파일 경로로 검증된 자식 프로세스)의 오디오
세션만 변경합니다.

- 시스템/마스터 엔드포인트 볼륨은 절대 건드리지 않습니다.
- 별도 드라이버나 대상 프로세스 수정 없이 동작합니다.
- Windows Core Audio API를 프로세스 외부에서 호출합니다.

## 실행

1. 내려받은 폴더에서 **`WindowsAudioKeys.exe`를 두 번 클릭**합니다.
2. `WindowsAudioKeys.exe.config`는 같은 폴더에 함께 두어야 합니다. 설치 프로그램은
   없으며, 이 두 파일만 있으면 바로 실행됩니다.

> 이 배포본은 코드 서명이 없습니다. 신뢰할 수 있는 서명을 요구하는 시스템 정책에서는
> 실행이 차단될 수 있습니다. 차단되면 실행을 중단하고, 해당 정책이 허용하는 정식
> 서명 빌드를 사용하세요. 보안 정책을 바꾸거나 차단을 우회하는 방법은 사용하지
> 마세요.

- Windows 11과 .NET Framework 4.8이 필요합니다.
- 일반 실행에는 저장된 설정이 있어도 설정 창이 열립니다. 로그인 자동 시작
  모드(`--startup`)에서만 트레이에 조용히 머뭅니다. 설정 창이 활성 상태인 동안에는
  전역 단축키가 잠시 해제되어 키를 편하게 고를 수 있습니다.
- 다른 앱으로 돌아가면 설정된 단축키가 다시 등록됩니다.
- 창을 닫거나 최소화하면 트레이로 숨겨집니다. 완전히 종료하려면 설정 창의
  **종료** 버튼 또는 트레이 아이콘 메뉴의 **종료**를 사용하세요.
- 이미 실행 중이면 새 인스턴스를 만들지 않고 기존 인스턴스 안내를 표시합니다.
  로그인 자동 시작 모드에서는 두 번째 실행이 조용히 종료됩니다.

### 위치와 업데이트

- 실행 파일과 `.config` 파일은 항상 같은 폴더에 함께 두세요.
- `WindowsAudioKeys.exe`를 다른 폴더로 옮기면 기존 자동 시작 작업은 이전 위치를
  가리킵니다. 이때 설정 창의 자동 시작 상태에 **등록 갱신 필요**가 표시되며,
  **자동 시작 적용**을 눌러 현재 위치로 갱신해야 합니다.
- 설정 파일은 실행 파일 위치와 무관하게 `%LOCALAPPDATA%\GameAudioKeys`에 보관되므로
  앱 폴더를 옮겨도 기존 오디오 단축키 설정은 유지됩니다.

### 실행 권한

일반 실행(두 번 클릭)은 사용자의 현재 권한으로 시작됩니다. 앱이 매번 관리자 권한을
요구하지는 않습니다. 다만 로그인 자동 시작을 켜면 자동으로 시작되는 인스턴스만
관리자 권한으로 실행됩니다.

대상 프로그램과 실행 권한 수준이 다르면 단축키 입력이 전달되지 않을 수 있습니다.
특정 프로그램에서만 단축키가 반응하지 않는다면 다음 절차를 확인하세요.

1. 설정 창의 **종료** 버튼을 누릅니다. 창의 X 버튼은 트레이로 숨기기만 합니다.
2. `WindowsAudioKeys.exe`를 우클릭하고 **관리자 권한으로 실행**을 선택합니다.
3. Windows 관리자 승인 창을 직접 확인한 뒤 대상 프로그램에서 단축키를 사용합니다.

다른 앱에서 정상 작동한다면 일반 권한으로 사용해도 됩니다. 이 앱은 자동으로 권한을
높이지 않으며, 수동 실행 시 모든 사용자에게 관리자 권한을 요구하지 않습니다.
Windows의 코드 무결성/앱 제어 정책이 실행 자체를 차단한 파일에는 권한 상승을
시도하지 말고 실행을 중단하세요.

## 기본 단축키

| 동작 | 기본 키 |
| --- | --- |
| 음소거 전환 | `Delete` |
| 볼륨 올리기 (+5%p) | `Page Up` |
| 볼륨 내리기 (-5%p) | `Page Down` |

- 볼륨 단계는 1~20%p로 바꿀 수 있습니다.
- 볼륨은 세션별 현재 값에서 상대적으로 변경되며 0~100%로 제한됩니다.
- 볼륨 단축키는 현재 음소거 상태를 바꾸지 않습니다.
- 대상 앱에 세션이 여러 개이면 모두 음소거 상태일 때 모두 해제하고, 그렇지 않으면
  모두 음소거합니다.
- 단축키는 사용 중인 동안 시스템 전역에서 예약됩니다. 대상 앱에 오디오 세션이
  없어도 키 자체는 예약되며, 이때는 아무 값도 바꾸지 않고 상태만 안내합니다.

## 설정 변경

1. 트레이 아이콘을 두 번 클릭하거나 메뉴에서 **설정 열기**를 선택합니다.
2. 각 동작의 키와 `Ctrl`/`Alt`/`Shift` 조합을 고릅니다. 키 목록은 키보드로도
   탐색할 수 있습니다.
3. 볼륨 단계를 정합니다.
4. **저장 및 적용**을 누릅니다. 저장 전에 제안된 조합을 실제로 등록해 보고,
   충돌하면 저장하지 않고 이유를 표시합니다.
5. **기본값**은 편집 상자만 기본값으로 되돌립니다. 적용하려면 저장을 누릅니다.
6. **트레이로 숨기기**는 설정 창만 숨깁니다. **종료**는 프로그램을 완전히 끝냅니다.

지원 키: `Delete`, `Page Up`, `Page Down`, `Insert`, `Home`, `End`, 방향키,
`F1`~`F11`, 영문 `A`~`Z`, 숫자 `0`~`9`. Windows 키, 수정자 키 단독, `F12`,
`Ctrl+Alt+Delete`, `Alt+Tab`, `Ctrl+Escape`, `Ctrl+Shift+Escape`, `Alt+F4`는
허용하지 않습니다. 같은 조합을 두 동작에 중복 지정할 수도 없습니다.

### 일시정지와 자동 일시정지

- 설정 창의 **단축키 사용**을 끄고 저장하거나 트레이 메뉴에서 **일시정지**를
  선택하면 단축키가 즉시 등록 해제됩니다. 일시정지 상태는 설정 파일에 저장됩니다.
- 일시정지 저장이 실패하더라도 이번 실행에서는 일시정지가 유지됩니다.
- 다시 시작할 때는 등록 가능 여부를 먼저 검사합니다. 충돌하면 일시정지 상태로
  남고 이유를 표시합니다.
- 이 앱의 설정 창이나 대화상자가 포그라운드이면 자동으로 단축키가 해제됩니다.
  다른 앱으로 돌아가면 다시 등록됩니다.
- 포커스 감시(WinEventHook)를 시작하지 못하면 안전을 위해 전역 단축키를
  등록하지 않고 오류를 표시합니다.

## 로그인 시 관리자 권한 자동 시작

설정 창의 **로그인 자동 시작** 그룹에서
**Windows 로그인 시 관리자 권한으로 자동 시작**을 켜고
**자동 시작 적용**을 누릅니다.

- 체크박스는 *원하는 상태*이고, **자동 시작 적용**을 눌러야 실제 Windows 작업에
  반영됩니다. 오디오 설정의 **저장 및 적용**과는 별개이므로 서로의 실패가 다른
  설정을 되돌리지 않습니다.
- 현재 프로세스가 관리자 권한이 아니면 Windows가 관리자 승인(UAC) 창을 한 번
  표시할 수 있습니다. 승인을 취소하거나 실패하면 실제 작업 상태는 바뀌지 않으며,
  앱은 다시 실제 상태를 읽어 그대로 보여 줍니다. 화면은 승인/등록 중에도
  응답합니다.
- 적용 결과는 추측이 아니라 Windows 작업 스케줄러에서 다시 읽은 실제 상태입니다.
  조회에 실패하면 꺼짐으로 표시하지 않고 오류를 표시합니다.
- 이 옵션을 켜도 *지금 실행 중인* 프로그램의 권한은 바뀌지 않습니다. 다음 로그인
  때 자동으로 시작되는 인스턴스만 관리자 권한으로 실행됩니다.
- 끄고 **자동 시작 적용**을 누르면 이 앱이 소유한 해당 사용자의 작업만 제거합니다.
  이미 없으면 오류 없이 그대로 완료합니다.

등록되는 항목은 다음과 같습니다.

- Windows 작업 스케줄러(COM `Schedule.Service`)의 루트 폴더에 있는
  `WindowsAudioKeys-<현재 사용자 SID>` 작업 하나.
- 현재 사용자 SID, 대화형 로그온 토큰(`InteractiveToken`), 최고 권한 실행
  (`HighestAvailable`).
- 현재 사용자 SID에 대해서만 동작하는 로그온 트리거 하나.
- 이 제품의 전체 경로와 `--startup` 인수, 실행 파일이 있는 폴더를 작업 폴더로 사용.
- 배터리 전원에서도 시작하고, 실행 시간 제한은 없으며, 중복 인스턴스는 무시합니다.
- 비밀번호는 저장하지 않으며 SYSTEM 계정이나 모든 사용자/부팅 트리거를 만들지
  않습니다. 시작 프로그램 폴더, Run 레지스트리, 서비스는 사용하지 않습니다.

같은 이름의 작업이 있더라도 이 앱이 만든 소유 표식과 현재 사용자 SID가 확인되지
않으면 덮어쓰거나 삭제하지 않고 오류로 안내합니다. 작업 스케줄러의 다른 작업이나
폴더는 건드리지 않습니다.

## 설정 파일

정확한 경로:

```text
%LOCALAPPDATA%\GameAudioKeys\settings.json
```

- 세 단축키의 키/수정자, 볼륨 단계, 사용 여부만 저장합니다. 자동 시작 여부는
  설정 파일이 아니라 Windows 작업 스케줄러의 실제 상태를 따릅니다.
- 비밀 정보는 저장하지 않습니다.
- 임시 파일에 쓴 뒤 원자적으로 교체합니다.
- 읽을 수 없거나 잘못된 설정 파일은 자동으로 덮어쓰지 않고 기본값으로 실행하며
  상태 창에 이유를 표시합니다.
- 잘못된 원본을 덮어써야 하는 저장(예: 트레이 일시정지)에서는 원본 바이트를
  `settings.json.invalid-<UTC시각>-<식별자>.bak` 형제 파일로 보존한 뒤 저장합니다.
  보존을 보장할 수 없으면 저장을 실패로 처리합니다.
- 기존 `GameAudioKeys` 설정 폴더와 JSON 형식을 그대로 사용하므로 업데이트해도
  기존 설정이 유지됩니다.

테스트 전용:

```powershell
.\WindowsAudioKeys.exe --settings-dir C:\temp\gak-settings
```

또는 환경 변수 `GAME_AUDIO_KEYS_SETTINGS_DIR`를 사용할 수 있습니다. 일반 사용에는
필요하지 않으며 UI에는 노출되지 않습니다. 테스트 설정 폴더를 사용하는 동안에는
자동 시작 작업을 조회하거나 변경할 수 없으며, UI와 도우미 모드 모두 이를
거부합니다.

## 빌드와 테스트

저장소 루트의 `WindowsAudioKeys.exe`와 `WindowsAudioKeys.exe.config`는 바로 실행할
수 있는 배포본입니다. 모델·사용자별 임시 빌드 산출물과 테스트 도구는 `bin`에만
생성됩니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

빌드 순서:

1. `bin`에 앱, 테스트, 진단 프로브, 오디오 픽스처를 컴파일합니다.
2. `-Test`를 지정하면 진단 프로브 자체 테스트와 앱 테스트를 먼저 실행합니다.
3. 모두 성공하면 `bin`의 앱과 설정 파일을 루트의
   `WindowsAudioKeys.exe` / `WindowsAudioKeys.exe.config`로 복사합니다.

`WindowsAudioKeys.exe`가 실행 중이면 빌드는 사용자 프로세스를 종료하지 않고
"먼저 트레이 메뉴에서 종료하세요"라는 오류로 중단됩니다.

테스트까지 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

- `AudioProbe.exe --self-test`: 진단 프로브의 26개 순수 로직 검증.
- `GameAudioKeys.Tests.exe`: 151개 검증. 기본값, 볼륨 클램프와 경계, 다중 세션
  토글 결정, 중복/예약/잘못된 단축키, 설정 왕복, 손상/무효 설정 보존, 저장 시
  `.invalid-*.bak` 보존, 공유 대상 선택 로직에 더해 자동 시작 인수 조합,
  작업 XML의 사용자/권한/트리거/경로/이스케이프, 소유/외부 작업 구분,
  누락/읽기 실패 상태, 계정 이름/SID 정규화, 적용 계획을 포함합니다.
- 테스트는 실제 작업 스케줄러 작업을 등록하거나 관리자 권한을 요청하지 않습니다.
  한 번의 비변경 플랫폼 검사에서만 생성된 XML을 실제
  `Schedule.Service.NewTask(0).XmlText`에 할당해 파싱/타입 계약을 확인하며,
  작업을 등록·수정·삭제하지는 않습니다.
- `AudioProbe.exe --list`는 읽기 전용 세션 진단입니다. 실제 오디오를 변경하지
  않습니다.

### 무음 오디오 픽스처 (테스트 전용)

```powershell
.\bin\AudioFixture.exe --auto-close-ms 9000
```

제목에 자신의 PID가 표시되고, 무음 PCM 스트림을 반복 재생해 실제 Core Audio
세션을 만듭니다. 인스턴스 뮤텍스가 없으므로 두 개를 실행하면 서로 다른 세션이
생깁니다. 창을 닫으면 오디오가 멈추고 임시 WAV가 삭제됩니다.
실행 중인 다른 프로그램의 오디오를 건드리지 않고 세션 제어를 시험할 수 있습니다.

## 알려진 제한과 주의

- 브라우저는 탭 단위가 아니라 프로세스 오디오 세션 단위입니다. 같은 브라우저
  프로세스의 여러 탭/창이 함께 음소거될 수 있습니다.
- 자식 프로세스는 **같은 절대 실행 파일 경로**를 쓰는 경우에만 대상으로 봅니다.
  동일 이미지 오디오 헬퍼는 처리되지만, 다른 실행 파일로 된 별도 오디오
  호스트/런처/업데이터는 대상이 아닙니다.
- 배타 모드 오디오, 일부 브로커/원격 세션, 보호된 프로세스는
  `ISimpleAudioVolume` 세션을 노출하지 않을 수 있습니다.
- 관리자 권한으로 실행된 앱, 다른 사용자 세션, 보호된 프로세스의 세션은 보이지
  않거나 읽기에 실패할 수 있습니다. 일반 실행은 권한 상승을 요청하지 않습니다.
- 세션의 상태/음소거/볼륨/인스턴스 ID를 정확히 읽지 못하면 아무것도 변경하지
  않습니다(fail closed). 일부 쓰기가 실패하면 변경된 세션의 원래 값을 복구하려
  시도하고, 복구 실패도 숨기지 않고 보고합니다.
- 포커스를 다시 확인한 직후에도 사용자가 포커스를 바꿀 수 있습니다.
- 엔드포인트/마스터 볼륨으로 대체하지 않습니다. 대상 세션이 없으면 실패를
  정직하게 표시합니다.
- `RegisterHotKey`는 다른 프로그램이 이미 등록한 조합과 충돌할 수 있습니다.
  충돌 시 다른 조합을 고르거나 일시정지하세요. 일부 프로그램은 Raw Input이나 자체
  키 처리 때문에 단축키가 예상과 다르게 동작할 수 있습니다. 이 앱은 저수준
  키보드 후킹이나 키 주입을 사용하지 않습니다.
- 사용 중에는 `Delete`/`Page Up`/`Page Down`의 원래 기능이 다른 앱에서 대체됩니다.
  원래 기능이 필요하면 일시정지하거나 `Ctrl`/`Alt`/`Shift` 조합을 지정하세요.
- Windows의 공개 오디오, 창, 작업 스케줄러 API를 사용합니다.

## 문제 해결

- **대상 오디오 세션을 찾지 못했습니다**: 대상 앱이 실제로 소리를 재생 중인지,
  출력 장치가 활성 상태인지 확인하세요. 음소거된 세션도 대상으로 잡히지만,
  오디오 스트림이 없는 앱은 세션이 없을 수 있습니다.
- **단축키 충돌**: 설정 창에서 다른 조합을 고르거나 트레이에서 일시정지하세요.
  저장 시 미리 등록해 보므로 영구적인 충돌을 성공으로 저장하지 않습니다.
- **특정 프로그램에서만 키가 반응하지 않음**: 위의 실행 권한 안내를 확인하세요.
  대상 프로그램과 도구의 실행 권한 차이 또는 해당 프로그램의 키 처리 방식이
  원인일 수 있습니다.
- **설정 창에서 키가 안 먹힘**: 정상입니다. 설정 창이 포그라운드이면 전역 단축키가
  자동으로 해제됩니다.
- **포커스 감시 오류**: 안전을 위해 단축키를 등록하지 않습니다. 앱을 재시작하고,
  계속되면 다른 보안/접근성 도구와의 충돌을 확인하세요.
- **자동 시작 상태 확인 실패**: 작업 스케줄러를 읽지 못한 상태이며 꺼짐으로
  간주하지 않습니다. 체크박스가 불확정 상태로 비활성화되며, 잠시 후 설정 창을 다시
  열어 상태를 새로 읽으면 정상적으로 복구됩니다.
- **등록 갱신 필요**: 실행 파일을 옮긴 경우입니다. 체크박스는 작업의 실제 사용
  상태를 그대로 보여 줍니다. **자동 시작 적용**을 눌러 현재 위치로 다시
  등록하세요.
- **자동 시작을 변경할 수 없음**: 같은 이름의 작업이 다른 프로그램/사용자 소유이거나,
  테스트 설정 폴더를 사용 중이거나, 관리자 승인이 취소된 경우입니다. 화면의
  안내를 확인하고 일반 실행에서 다시 시도하세요.
